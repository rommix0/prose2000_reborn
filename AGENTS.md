# AGENTS.md

Decompiling and emulating the **Speech Plus / Telesensory Systems Prose 2000/2020**
text-to-speech synthesizer (8086 + NEC µPD77P20 formant-synthesis DSP), for use as an NVDA voice.

Keep this file short. Details live in [REFERENCE.md](REFERENCE.md), so read only the
section you need: `grep -n '^## ' REFERENCE.md`.

## Key facts
- 8086 @ 8 MHz. ROM at `C0000-FFFFF`, SRAM at `00000-02FFF`. I/O is memory-mapped at
  `0x3000` (8251), `0x3200` (8259), `0x3400/01` (DIP / param reg) and `0x3600/02`
  (7720 data/status). Full map: REFERENCE §2.
- The DSP produces audio at 10 kHz through its **serial output** into a 12-bit DAC. The
  8086 feeds it a frame **every 10 ms**, driven by 7720 P0 → 8259 IR0. The frame is
  **40 words = 80 bytes of precomputed resonator coefficients and amplitudes**: the 8086
  converts the 22 parameters, and the DSP only filters. The handshake is USF0 = "want frame"
  plus RQM per byte; the ports are `3600/3602` on the 2000 and `3000/3002` on the 4001.
  Silence frames set bit `0x80`. Decompiled and verified: REFERENCE §11.
  **DSP program decompiled** (Klatt cascade/parallel, pitch-synchronous F1-F3): REFERENCE §13; C in `src/`.
- **Parameter generator** `paramgen_run` `DCB00`: per-phoneme targets (58 phoneme codes, `DS:93CA` char→index) plus
  class-pair rules, written as 22 byte tracks (AV AF AH A2-A6 AB F1-F4 B1-B3 FN F0 …; codings in §11.4). Structure
  verified; to watch it, sample `DS:DC46` (= RAM `01D46`) every 10 ms. REFERENCE §12.
  **Decompiled to C** (`src/paramgen/`, byte-exact on 11k captured calls); C works on an image of the DS segment. §12.7, §14.
- **Pipeline:** `synthesis_loop` `E39A7` runs 5 stages over one node list, later stages first: **input `DE09D` (decompiled; §15.5)**, **text
  rules `D41A4` (decompiled: a byte-code rule interpreter for numbers, abbreviations, symbols, phoneme input; hands
  on one word at a time; `src/textrules/`, §15.4)**, **lexical `E4A81` (decompiled: lexicon, affixes, right-to-left
  letter-to-sound rules, stress, allophone rules; `src/lexical/`, §15.3)**, **prosody `D9274` (decompiled: Klatt
  durations, F0, phrasing; `src/prosody/`)**, paramgen, then playback `D40F4` (frees played nodes, reports
  markers). Stage records at `DS:C206 + 0x22·k` carry each stage's
  cursors and its copy of the host settings.
  Node kinds: 0 command, 1 input text, 2 text, 3 symbol, 4 timed segment, 5 hold. `D38B8` is `node_next` (follows `+0`). REFERENCE §15.
- Pipeline per the patent [216]: normalize → dictionary → letter-to-sound → stress → consonant allophonics →
  prosody → parameter generator → formant DSP. Phoneme set: 23 vowels,
  33 consonants and silence. REFERENCE §5.
- US4979216A (vowel allophone codebooks) describes a *reprogrammed* Prose 2000.
  Whether v3.4.1 contains those tables is **unverified**. REFERENCE §6 lists the
  table formats and search heuristics.
- The S4-7 DIP switch enables the firmware's self-test speech loop.
- The host talks to the firmware with inline `ESC [ n <letter>` commands. **Verified in
  emulation:** voice `V` (0-2), amplitude `a` (higher = quieter), pitch `p`, rate `r`/`v`,
  word mode `P`, pause `s`, phoneme input `I`, and end of sentence `x`.
  `X` and `c` get a BEL reply, meaning unsupported. The firmware replies `ESC[0R` at
  reset and `ESC[0x` when a sentence is done. The final punctuation must be followed by
  a space, CR or LF (CR/LF/TAB become spaces), or by `ESC[x`. README.md's claim of a
  single voice is out of date. REFERENCE §8.
- **Escape parser decompiled** (4001 `host_escape_parser` `D6462`; 2000 `D658C`, in C: `src/input/in_escape.c`). It
  knows 28 commands; most are forwarded *in-band* so they apply at that point in the speech. There are index markers
  `ESC[n i`, a status query `ESC[Q`, and identify `ESC[E` → `ESC[34E`. Full table: REFERENCE §8.1-8.2.
- **After `ESC[x`, wait for the `ESC[n x` reply before sending more text**: when the `x` is spoken the firmware resets
  the pipeline and both host rings, so text that arrived before then is lost (verified; REFERENCE §15.6). **While an
  `ESC[x` is pending, the next index marker ends the utterance**, so `text ESC[1i more ESC[x` loses "more" (§8.2).
- **`ESC[16N` = phoneme echo:** the firmware sends each phoneme (plus stress digits and punctuation) as it is spoken,
  e.g. "Hello, my friend." → `HeLO1 ,MIFRe1NDp  . `. The 1-char **phoneme alphabet → IPA** table is in REFERENCE §12.3a.
- The phoneme-spelled exception dictionary is at about `F44D8-F6225`. REFERENCE §5.
- **Lineage:** MITalk → Prose → Centigram **TruVoice** (`..\TruVoice_disasm\TV_ENG32.DLL`), and separately
  MITalk → DECtalk (`..\DTC-01`). About 38 KB of Prose linguistic data appears **verbatim** in the DLL:
  the lexicon, the feature table, affix tables, the exception dictionary, and the **parameter-generator targets**
  (TruVoice `100122E0` = `paramgen_load_targets`). DECtalk shares only number words.
  Functions and tables named in one project transfer to the other. REFERENCE §9.
- **OpenTV** (`..\tv-decomp-main`, third party): a byte-exact C decompilation of TruVoice `CGRM_EN.DLL`. Its back end is
  a port of ours: `frame.c` builds the **same 40-word DSP frame**, and `generate.c` is the best guide to the µPD7720
  filter program. Its addresses are CGRM's. Tag its claims **[tvd]**. REFERENCE §1, §11.3.
- Data segment **`DS = F410`** (`DS:x` = `F4100+x`). The lexicon is segment `E900`, looked up by
  `lex_lookup` `D738A`, which is the same algorithm as TruVoice `10074f90`. REFERENCE §9.3-9.4.

## Working rules
- Treat patent statements as hypotheses until you confirm them in ROM or in emulation.
  Label findings as *verified*, *inferred* or *patent-claimed*.
- The firmware is proprietary **abandonware**: the company no longer exists, and neither does its
  successor Centigram (TruVoice) (user's statements, 2026-09-25).
  **Extracting the ROM's data contents (rule tables, lexicon, targets, DSP tables) is required for this project**,
  so the C can run without the ROM files. Put extracted data in data files or generated C tables, not in the docs:
  REFERENCE.md keeps addresses, structure descriptions and short excerpts.
- Use linear 20-bit addresses for the 8086 (e.g. `E3987`), matching MAME's notes.
- The DSP data ROM is word-swapped, and program words are packed 24-bit. See `prose_v3/tsispch.cpp:246`.
- When you verify a new fact (a routine, table or I/O behaviour), add it to REFERENCE.md,
  not here. Add a one-line pointer here only if it will be needed on most tasks.
- Build the emulator out-of-tree:
  `cmake -S native -B <dir> -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build <dir>`.
  Then run
  `prose_cli prose_v3 <cycles> "<text>\r" out.wav`. About 110 M cycles covers one
  sentence. Windows filenames are case-insensitive, so `V1.wav` and `v1.wav` collide.
- **Ghidra** (via `ghidra-mcp`, tools deferred; load them with ToolSearch): project `prose2000_disasm`
  has three programs, all imported raw as `x86:LE:16:Real Mode`. **Always pass `program`.**
  - **`prose4001_v341_D0000.bin`** (preferred for code reading): the Prose 4001 ISA card, 80188. It holds the
    same v3.4.1 firmware, with linear ROMs u3/u2/u1 → `D0000/E0000/F0000` and base `d000:0000`. It has 192
    functions, seeded by scripts. REFERENCE §10.
  - **`prose2k_v341_C0000.bin`**: the Prose 2000, a 256 KB interleaved image with base `c000:0000`
    (`prose_v3/`). Use it for the 2000's board I/O.
  - **`prose2k_v11_cs.bin`**: the older v1.1 (1983) set, merged from `prose_v1/`. Only its code segment `EC00` is
    imported, at base **`0000:0000`**, so an address is the offset: linear = `EC000` + offset.
    An ancestor with a different program and a 37-word DSP frame, not a variant: REFERENCE §16.
  - Named functions exist in both. The address map between them is in REFERENCE §10.3.
  - `run_script_inline` works (Java `GhidraScript`). The server writes the script into
    `C:\Users\abart\ghidra_scripts\` while it runs and removes it afterwards. The error about a failing
    `InlineScript.java` there comes from an older, unrelated file and is harmless. Ghidra names addresses `d000:xxxx`/`e000:xxxx` (linear = seg·16+off).
  Far calls use segments `D35C`, `D5D6`, `D310`, `D345` and others, so auto-analysis finds only part of the
  code; create functions at far-call targets. Name functions in snake_case. The server's
  PascalCase warnings can be ignored.
- Environment: Windows, Git Bash plus PowerShell. `python` is 3.13 and there is no `python3`.
  ImageMagick (`magick`) renders PDF pages. `pdftoppm` is not installed.
